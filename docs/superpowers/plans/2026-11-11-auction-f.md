# Auction Screens (UX step F) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to carry out this plan one task at a time. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Style Bible screens 8–11 (`client/public/style-bible/index.html`, section "Auction"): live bidding, putting a player up, commissioner controls and the team board. Also delete about 3,000 lines of dead legacy auction code. The Style Bible's own plan: **keep the engine, rebuild the screens.**

**Spec gaps the Style Bible lists, all fixed here:**
- There is no phone layout, so bid buttons scroll away.
- Other teams' money is hidden on a separate tab.
- Text is 8–11px.
- You can only bid +$1 or +$5; there is no way to type an amount.
- The commissioner can't pause during a turn to put a player up (the pause isn't visible).
- Some controls need the site admin.
- There are about 2,900 lines of dead copies, plus a "classic" page that duplicates the new one.

**Architecture:**
- **Server:** the existing Express auction module at `server/src/features/auction/`. State lives in memory, is persisted to `AuctionSession.state`, and is broadcast over the WebSocket `/ws/auction`. The changes are small and additive: new state fields, three engine fixes, one new endpoint for skipping a turn, a server-side "my list" for each team, and commissioner (not admin-only) authorization on the controls the spec gives the commissioner.
- **Client:**
  - `/auction` is rebuilt as one page with a phone layout under 768px and a desktop layout at 768px and up. Same URL, chosen by media query inside the page; the auction has no MobileShell twin.
  - It keeps `useAuctionState`, `useAuctionSounds`, `useAuctionNotifications` and `useAuctionPrefs`.
  - Results: `/auction-results` becomes the team board. The existing results view (grades, charts, replay, report) moves to `/auction-results/report`, one tap away.

**Tech stack:** React + Vite + vitest/RTL on the client; Express + vitest + supertest on the server.

## Rulings (planning decisions; mine unless noted)

1. **Keep the engine.** No changes to bid or finish money math, `calculateMaxBid`, roster writes or persistence format. Only additive state fields.
2. **New state fields:**
   - `nominationEndTime: string | null`, set whenever the nomination timer is scheduled, so the 0:22 clock can render.
   - `paused: boolean`, true between `/pause` and `/resume` in **both** phases.

   Both go in `server/src/features/auction/types.ts` and are mirrored in `client/.../hooks/useAuctionState.ts`. Old persisted states without them load as `null` / `false`.
3. **Engine fixes (bugs found reading the code; each gets a route-level test):**
   - a. `/bid` rejects with 409 `"Auction is paused"` when `state.paused` or `nomination.status !== 'running'`. Today a bid during a pause, inside the old window, goes through and restarts the timer. The same guard goes on `/proxy-bid` placement only if proxy placement can trigger a bid; check `biddingRoutes` and apply consistently.
   - b. `/nominate` rejects with 409 unless `state.status === 'nominating'`, the auction isn't paused, and `nominatorTeamId === state.queue[state.queueIndex]`. **Exception:** a commissioner or admin may nominate for the team whose turn it is (`isAdminOrCommissioner`). Today only the client enforces turns.
   - c. Resuming during a turn restarts that team's clock with full time (unchanged), and now also sets `nominationEndTime`.
4. **Commissioner authorization:** `/undo-finish` and `/complete` move from `requireAdmin` to `isAdminOrCommissioner` (the pattern `/pause` uses). `/init`, `/reset` and `/finish` stay admin-only; the spec doesn't give them to the commissioner. Leave the existing "Start auction" screen's logic alone, just restyle it.
5. **Skip turn:** new `POST /api/auction/skip-turn?leagueId=`, commissioner or admin, only while `status === 'nominating'`. It reuses `advanceQueue` (completing the auction if every roster is full), reschedules the nomination timer, logs, broadcasts and persists.
6. **Every fix is logged.**
   - New `log` event types: `SKIP`, `ASSIGN`, `END` (UNDO and PAUSE/RESUME exist).
   - Also `writeAuditLog` for skip-turn, force-assign and undo-finish, matching `/complete`'s use.
   - Extend the log type union on both server and client.
7. **"My list" moves to the server** so the clock running out can put up the top of your list, which is what the spec asks for.
   - Stored in auction state as `nominationLists: Record<teamId, number[]>` (mlbIds, ordered) and persisted with the state. **Never broadcast:** strip it in `auctionWsService`'s broadcast and in `GET /state`, the same way proxy bids are stripped.
   - `GET /api/auction/my-list?leagueId&teamId` and `PUT /api/auction/my-list` (`{teamId, mlbIds}`, max 50), both team owner only.
   - On first load the client migrates the existing localStorage `nominationQueue_${teamId}` once via PUT, then deletes the key.
   - **Auto-put-up:** when the turn clock runs out, the server takes the first mlbId on that team's list that is not rostered, not already sold in this auction, and passes `checkPositionLimit`. It nominates that player at $1 through the **same core function** `/nominate` uses. Extract `nominatePlayer(leagueId, state, {...})` from the route; the timeout must not re-implement it.
   - Player name, positions, team and isPitcher come from the `Player` table by mlbId.
   - An empty or exhausted list means skip, as today, logged `SKIP` with reason `timeout`.
8. **Bidding UI:**
   - The first button bids current+1, the second current+5.
   - `Type an amount` opens an inline number field with a `Bid` button.
   - Client validation: a whole number, greater than the current bid, at most `myTeam.maxBid`. The server stays the authority and its error is shown inline.
   - Hide or disable the bid controls when you are the high bidder, when the auction is paused, or when you have no team.
   - The max bid (proxy) control keeps the existing `/proxy-bid` endpoints.
9. **Needs** come from a pure client function `teamNeeds(team, config)`. It uses `config.positionLimits` and `team.positionCounts` or `team.roster` slots, and **must be checked against the real `loadPositionLimits` output shape before it is written** (read `server/src/features/auction/` for its source).
   - Output looks like `C, SS, OF ×2, P ×5`. Board groups: `C`, `1B · 2B · 3B`, `SS · MI · CI`, `OF ×N`, `P ×N`.
   - If a league's limits don't fit these groups, fall back to listing raw slots. Don't hardcode OGBA.
10. **Bids on this player** is the `log` BID entries after the latest NOMINATION, newest first. **Last sales** is the `log` WIN entries, newest first, top 5.
11. **Player values:** reuse what the current `PlayerPoolTab` uses (`dollar_value ?? value` from `getPlayerSeasonStats`). Show plain value; the old "My value" personalization is dropped from the main screens.
12. **Dropped from the auction screens (my call, listed in the PR):**
    - the Chat tab (the server's `CHAT` WebSocket messages stay)
    - the Settings tab (sound and notifications become two small toggles in the page header)
    - rankings import
    - the starred watchlist
    - AI bid advice

    The spec draws none of them. Their server endpoints stay.
13. **Results:**
    - `/auction-results` renders the screen-11 board from `GET /auction/results` (the snapshot) with `Grades and charts ›` linking to `/auction-results/report`, which renders the existing `AuctionComplete`.
    - During the auction the board is the phone `Board` tab and the desktop route `/auction/board`, with a link to it from the desktop header.
    - When `status === 'completed'`, `/auction` shows the board, not AuctionComplete.
14. **Deletions:**
    - The 10 `*Legacy.tsx` components, `AIAnalysisTab.tsx`, `AuctionTab.tsx`, `features/auction/index.ts` (barrel with no importers) and `pages/AuctionLegacy.tsx`.
    - `/auction-classic` becomes a redirect to `/auction`.
    - Then every component the rebuild leaves unimported: expected AuctionLayout, AuctionStage, TeamListTab, PlayerPoolTab, PlayerExpandedRow, NominationQueue, MyNominationQueue, ContextDeck, ChatTab, AuctionSettingsTab, AuctionDraftLog, and hooks useWatchlist / useMyRankings / useNominationQueue.
    - **Prove each one dead with grep before deleting.**
    - Keep AuctionComplete, DraftReport, BidHistoryChart and AuctionReplay (the report), and AuctionValues.
    - Fix `__tests__/AuctionCompleteCard.test.tsx`, which imports the legacy file.
    - Fix the stale `/auction-results-classic` comment.
15. **The player card** opens from player names on all four screens, through `<PlayerLink>` / `usePlayerCard` from step E.

## Review focus

1. **Turn enforcement:** a non-commissioner owner nominating out of turn gets 409. The commissioner's on-behalf nomination works. The client's "Put up" only shows on your turn.
2. **Pause:** a bid while paused gets 409. Pausing during a turn stops the turn clock, and every client sees `paused`. Resume restores the right clock.
3. **The timeout auto-put-up** never nominates a rostered or already-sold player, or a player the team's position limits forbid. It uses the shared nominate core (one code path), and **my-list never appears in any broadcast or GET /state payload.** Test by asserting on the broadcast payload.
4. **Typed bids:** non-integer, too low, or above max are rejected client-side, and the server's message is shown when the server rejects.
5. **Phone:** the lot header stays pinned while the Teams/Players/Board tab content scrolls. No sideways scroll at 390px.
6. **Auth:** a non-admin commissioner can pause, undo, skip, assign and end. A plain owner gets 403 on each.
