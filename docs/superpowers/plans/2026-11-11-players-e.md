# Players Table + Player Card (UX step E) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Style Bible screens 6–7. One players table for the whole app, and a player card that opens when you tap a player's name.

**Architecture:**
- **Server:** one new cached endpoint, `GET /api/players/:mlbId/card`. It assembles the card from statsapi through `mlbGetJson`, which is already cached in SQLite: date-range splits, season, last season, the game log and the next game.
- **Client card:** a shared `PlayerCard` mounted once by `PlayerCardProvider`. It slides up as a bottom sheet on phones and opens as a right-hand panel on desktop. `usePlayerCard().open(mlbId)` opens it from anywhere.
- **Client table:** one shared `PlayersTable` replaces the desktop `Players.tsx` body and the `MobilePlayers` twin.

**Tech Stack:** React + Vite + vitest/RTL (client); Express + vitest + supertest (server); statsapi.mlb.com through `server/src/lib/mlbApi.ts`.

**Spec:** Style Bible screens 6–7 (artifact UDWjhsrCsDKxovbSjkyPXc) and the step E outline in the roadmap artifact 2ZwcUjSmsWTMZ34GjCU5vS.

## Global Constraints

- **Style Bible type and color.** Four text sizes only (13/15/17/24px), nothing under 13px, Sofia Sans; use the existing tokens. The step A test that blocks small sizes must stay green.
- **No modals,** except irreversible confirms, the player-card peek and auth. The player card IS the allowed peek: a bottom sheet on phones (< 768px), a right-hand panel on desktop, with the list still visible.
- **ADR-015, no cross-feature imports.** The card lives in `client/src/components/shared/`. The players feature gets its own local wrapper for the Wire List add endpoint.
- **Phone 390px:** no sideways scroll. On phones the table's five stats sit under the name.
- **Copy:**
  - Column headers: `Player`, `MLB`, `Pos`, `Fantasy team`, `R HR RBI SB AVG` for hitters and `W SV K ERA WHIP` for pitchers, then `Action`.
  - Action buttons: `+ Wire List`, `Trade`.
  - Card ranges: `Last 7 days`, `Last 14`, `Last 30`, `Season`, `Last season`.
  - Card sections: `Last 5 games` (hitters), `Last 3 starts` (pitchers), and the link `Full profile ›`.
- **Card stat lines:** hitters `AB R HR RBI SB AVG`; pitchers `IP W SV K ERA WHIP`.
- **"Last N days" are calendar days,** ending yesterday in US Eastern time. These are the days owners are scored on.

## Rulings (planning decisions)

1. **The table's range menu offers `Season` and `This period` only.** This period reads the existing `/api/player-period-stats`. Last 7/14/30 live on the card. Doing them for every row would need about 1,500 statsapi calls.
2. **Actions in season:**
   - `+ Wire List` on free agents, when a pending period exists. It adds to the owner's Wire List for that period.
   - `Trade` on players owned by another team. It links to `/trades/new?team=<teamId>&get=<playerId>`, and New trade preselects that team and player.
   - No action on the owner's own players.
   - The auction's `+ List` is step F. The table takes a `mode` prop, but this step only ships `"season"`.
3. **The watchlist star moves from the rows to the card header.** It keeps the feature without a fourth column.
4. **The card replaces `PlayerDetailModal` at every call site** (10 files). The modal and its test are deleted, and `/players/:mlbId` stays as the "Full profile" page.
5. **Where the card opens from in this step:**
   - the players table;
   - every former modal call site;
   - the Today page's player rows;
   - the roster hub.

   Other plain-text names (standings drill-downs, commissioner and trade screens) get the card in a follow-up sweep, listed in the PR.
6. **Next game** comes from statsapi `schedule` for the next 7 days, shown as "LAD vs SD tonight 7:10" or "@COL Fri 6:40". If there's no game in that window, the line is omitted.
7. **Off-season** (season stats empty): the card opens on `Last season`.
8. **Two-way players** keep two table rows (existing `expandTwoWayPlayers`). The card shows a Hitting / Pitching switch only for two-way players.
9. **No new tables and no migration.** The cache is the existing SQLite `mlbCache`, with a 30-minute TTL on card responses.

## Review Focus

1. **A player with no MLB games** (minor leaguer, injured all year): the card shows "No games yet" and doesn't crash on empty splits.
2. **`mlbId` missing or non-numeric:** the endpoint returns 400, and names without an mlbId aren't tappable.
3. **The phone sheet** closes on swipe or backdrop tap, returns focus to the name, and the page behind doesn't scroll.
4. **Tapping a second name while the card is open** swaps the player without stacking panels.
5. **statsapi down:** the card shows "Couldn't load stats. Try again." and the table still works.

### Task 1: Server card endpoint

**Files:**
- Create: `server/src/features/players/services/playerCardService.ts`
- Modify: `server/src/features/players/routes.ts` (add `GET /:mlbId/card` before `/:mlbId`)
- Test: `server/src/features/players/__tests__/playerCard.test.ts`

**Interfaces:**
- **Produces:** `GET /api/players/:mlbId/card?leagueId=N` → `PlayerCardData`:
  `{ mlbId, name, pos, mlbTeam, isPitcher, isTwoWay, fantasyTeam: {id,name,code}|null, nextGame: {opp, home: boolean, startUtc}|null, splits: {last7,last14,last30,season,lastSeason}: Record<string,number|string>|null per group, recent: GameRow[] }`
  where `splits` and `recent` are keyed by group `hitting` / `pitching`. `GameRow = {date, opp, home, line: Record<string,number|string>}`. `recent` holds the last 5 games for hitting and the last 3 starts (`gamesStarted===1`) for pitching.
- **Service:** `buildPlayerCard(mlbId: number, leagueId: number, today: Date): Promise<PlayerCardData>`. `today` is injected so tests are deterministic.

- [ ] Test `computes calendar windows ending yesterday ET`. With today 2026-06-11T15:00Z, last7 asks for `startDate=2026-06-04&endDate=2026-06-10`. Assert on the URL passed to the mocked `mlbGetJson` (memory: a mock can't catch a wrong query, so assert on the args).
- [ ] Test `last 3 starts skips relief appearances`. Use a game log with 5 pitching games, 2 of them with `gamesStarted: 0`.
- [ ] Test `picks the MLB split, not the all-sports one`. Verified 2026-11-11: `byDateRange` returns one split with `sport.id 1` (MLB) and one with `sport.id 0` (All, which can include the minors). Use the `sport.id === 1` splits. If there are several (a traded player), take the one with no `team` key; if every split has a team, sum the counting stats and recompute AVG, ERA and WHIP.
- [ ] Test `empty splits yield null, not a crash`.
- [ ] Test `400 on non-numeric mlbId`.
- [ ] Test `fantasyTeam comes from the active Roster row in that league` (releasedAt null).
- [ ] Implement. Fetch the splits in parallel with `Promise.all`; each `mlbGetJson` call goes through the existing cache. Card endpoint TTL is 30 min.
